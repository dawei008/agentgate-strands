# 0013 长文交付物住在页面上，不住在浮层里（内容量决定容器）

Status: accepted（2026-08-27）
Extends: [0011 浮层三分法](0011-overlay-taxonomy.md) —— 0011 定「用哪一种浮层」，
本条定**它前面那个问题**：该不该用浮层。

## Context

评估报告原本是右侧抽屉（`ReportDrawer.tsx`，宽度 600 → 1080）。用户原话：

> 评估报告抽屉式看着太费劲，很多字但只有一半屏幕能看，除非抽屉式默认更大区域或可调。

**先做过一次「只治宽度」**（`9a26738`：600 → 1080 + 富余宽度进并排证据列 +
`--rd-measure: 44em` 限行长）。那一批本身是对的、也留着，但抱怨没有消掉 ——
因为宽度不是唯一的成本。抽屉在这个内容量上还欠三件：

- **遮罩 + 焦点圈禁**是为「填完就走」设计的：一份要读几分钟的长文被关在里面，
  用户既不能同时看运行列表，也不能中途去别处；
- **没有地址**：报告不可加书签、不可后退、不可分享。而报告是平台的**交付物**
  ——「发给同事看」是它的主用途之一，浮层结构上做不到；
- **1080 也只是屏幕的一部分**：`maxWidth: 92vw` 之下，抽屉永远比页面窄。

⇒ 抱怨的对象是**形制**，不是那个数字。加宽是在形制内部找余地，而余地已经用完。

## Decision

**内容量决定容器：超过约一屏的连续长文，一律用页面，不用浮层。**

| 内容量 | 容器 | 现有落点 |
| --- | --- | --- |
| 一屏内的表单 / 确认 / 菜单 | 浮层三分法（见 0011） | `FormDrawer` / `ConfirmCard` / popover |
| **超过一屏的长文交付物** | **独立页面 + 可分享路由** | 报告 `#/report/<run_key>`（`pages/report/ReportPage.tsx`）、对比 `#/compare`（`pages/compare/ComparePage.tsx`） |

配套四条硬规则：

1. **一份视图，两个壳**。正文只有一份实现，外壳（页 / 抽屉）通过 `entry` prop
   区分，只决定外框与吸顶基准。报告：`plan/ReportView.tsx` +
   `pages/report/ReportPage.tsx` + `plan/ReportDrawer.tsx`（77 行薄壳）；
   对比：`plan/compare/CompareView.tsx` + `pages/compare/ComparePage.tsx` +
   `CompareDrawer.tsx`。理由：**同一个 run 在两处读出两个结论，比读出一个错结论更难查。**
2. **一个对象一个地址**。路由参数只带用户所指的那个对象，系统的容器不进 URL ——
   报告路由是 `#/report/<run_key>`，方案 id 从 run_key 前缀（`<plan_id>#<ts>`）
   现推。两段式 `/plan/:id/run/:key` 会让同一份报告有两个可分享地址。
3. **一个入口一件事**。成页之后**不保留通向抽屉的生产入口** —— 一颗「查看报告」
   不能既跳页又开抽屉。两个门会把「我点这个会得到什么」的歧义原样请回来。
   薄壳留在仓库里是为了让回退是一行改动，不是为了同时上线。
4. **吸顶条要 `overflow: visible` 的祖先**。`.card` 自带 `overflow: hidden`
   （`styles/ui.css:258`）⇒ 页内长文卡必须显式 `overflow: visible`，否则
   `position: sticky` 的分节锚点条与操作条**不报错、不掉样式，只是不吸顶**，
   与「压根没写 sticky」同形。（同族第一形是 0011 第 6 条那次线上事故：
   `backdrop-filter` 祖先夹扁 `position: fixed` 抽屉。**`.card` 一个属性坑过两次，
   两次的症状完全不同。**）

## Consequences

1. **0011 没有被推翻，射程被补了一句**：0011 第 5 条 Consequences 说「报告抽屉等
   既有浮层已符合三分法」—— 那句在「它该是浮层」这个前提下为真，本条改掉的正是
   那个前提。0011 对**表单/确认/菜单**的六条硬规则一字不动。
2. **视觉基线的载体变了**：`14-report-drawer` / `18-report-advice` 两条计划项的
   `hash` 改为直指深链（不再点方案页那颗按钮）。附带好处是报告基线不再拴在
   **运行历史表格的 markup** 上 —— 那张表刚在 `7866b06` 加过勾选列。
   ⚠️ 名字里的 "drawer" 是**过时的词，刻意不改**：改名会让这两条成为新面
   （首截百分比无定义），基线血统会断。
3. **`full_page` 仍然不许开**（配方不变，理由换了）：成页后滚动容器是 `window`，
   技术上抓得全整份报告 —— 但 Playwright 的 fullPage 把 `position: sticky` 按
   **原视口**解算，吸顶条会被画在首屏底边**压住正文**。⇒ 照旧「给足视口高 +
   `full_page: false`」，18 继续用 1800×1900。
4. **测试挂载点是页壳，不是共享视图**：阵营归类要 `plan.stages`，而「从 run_key
   推方案 id」这一步正是页壳在做 —— 挂 `ReportView` 会把这一步测空。
5. **jsdom 缺 `window.scrollTo`**，且缺失**只在成页路径上抛**（抽屉不滚 window）
   ⇒ 这道缺口在改成页之前结构上不可能红，`web/tests/setup.ts` 补了空实现。
6. **本条不是「以后都别用抽屉」**：判据是内容量与用途（读 vs 填），不是新旧。
   资源库表单、设置、确认卡一律照 0011 走。
