# ADR-0014: 运行报告只讲本次，跨 run 内容全部归评估分析

日期：2026-08-31 · 状态：已采纳（用户 grilling 终审）

## 背景

运行报告改了很多遍仍「看不懂」（用户 2026-08-31）。历次修补（分部标题、
层次化、无废话、引用修复）都没治本，根因是**信息架构错位**：第一屏是
「① 本次运行的环节」数据表——先给数、不给结论；② 综合报告四段（整体趋势/
反复出现的问题/改进采纳效果/当前优先建议）前三段全是跨 run 内容，与
「这一次跑得怎么样」互相稀释。

## 决定（九连问逐条终审）

1. **报告只讲本次。** 任何跨 run 内容（趋势、反复问题、采纳效果追踪、
   跨 run 优先建议）一律迁评估分析页。报告里不出现「较上次 ▲0.07」。
2. **第一屏 = 一句裁决，裁决即头部。** 现算事实句只列本次没过的东西
   （「红队被攻破 1/3 · 回归 1/2 没过 · 线上 2 会话全部过线」；全过 =
   「全部过线」）。徽章排废除；时长/触发/成本保留为小字元信息行。
3. **不分档。** 「要管/注意/正常」这类二手词不造——裁决句直陈失败数即裁决。
   判定全部用 SDK 自带 `test_pass`，不发明阈值、不比上次，任何人可复核。
4. **全量表为主体，一张表管三个环节。** 一行 = 一个用例/会话/攻击；按环节
   分组、均分在组头；失败行标红置顶。行内评估器小格（分+过/不过）；红队行
   判定列只有攻破/守住。不设独立的「没过的逐条」区——证据链住失败行展开态。
5. **展开态顺序**：judge 判词（label+分+reason）→ 原文对照（输入/输出/期望）
   → 诊断（失败分类+根因+修法）→ 跳 trace。
6. **本次建议区**（对标海外区 AgentCore optimization Recommendations 输出形状）：
   只聚合本次诊断产物，按改法分组（改系统提示词/改工具描述/其他 = SDK
   `fix_type` 三值）；每条 = 具体修法 + 根因理由 + **必须引用支持它的评估
   结果**（失败行可点跳）——**无引用不上屏**；按覆盖失败数排序；采纳按钮
   保留，采纳后的效果追踪在评估分析页。
7. **设计立足 SDK 返回物**：EvaluationOutput（score/test_pass/reason/label）+
   diagnoses（FailureItem: category/evidence；RCAItem: root_cause_explanation/
   causality/fix_type/fix_recommendation）。报告不要求 SDK 没有的东西。

## 后果

- ReportView 三块重写：裁决句头部 / 全量表 / 本次建议区。
- 综合报告四段 + 采纳追踪迁评估分析页 = 独立批次（迁移前旧区先下线，
  评估分析吃进去之前那些能力短暂不可见——用户已确认「四段全迁走」）。
- 空 run 沿用「完成 · 无可评估数据」中性口径（ADR 外既有裁决）。
- 页脚「与上次对比」按钮保留为跳评估分析的门（门不是内容）。
